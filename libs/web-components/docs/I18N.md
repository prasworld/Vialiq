# Internationalisation (i18n) — `@vialiq/web-components/i18n`

**Module:** `libs/web-components/src/i18n/`  
**Directive:** `translateDirective` (aliased `t`)  
**Strategy:** JSON translation files loaded asynchronously at app startup  
**Runtime:** Lit directive — renders translated strings reactively inside Lit templates  

---

## Overview

All Vialiq web components that render **internal** text (ARIA labels, button labels, placeholder fallbacks, status messages) use the `translateDirective` rather than hardcoded English strings. Text passed in by the **consumer** (via attributes, slots, or properties) is never translated by the component — only component-owned strings go through the directive.

Examples of **internal** strings (i18n-controlled):
- `vi-tabs`: "Close", "Add tab", "More ({count})"
- `vi-combobox`: "No results", "Loading…", "Create…"
- `vi-file-upload`: "Drag files here", "Browse", "Remove file"
- `vi-modal`: "Close" (header × button)
- `vi-alert`: ARIA live label prefix
- `vi-toast`: ARIA label prefix
- `vi-time-picker`: "Time unknown"
- `vi-month-year-picker`: month name abbreviations (delegated to `Intl.DateTimeFormat`)

Examples of **external** strings (NOT translated by the component):
- Tab labels, button labels set by the host app
- Placeholder text provided via the `placeholder` attribute
- Toast message and title content

## `translateDirective` — The Directive

The directive is a Lit `AsyncDirective`. It renders translated strings inside Lit `html` templates:

```typescript
// libs/web-components/src/i18n/translate-directive.ts
import { directive, AsyncDirective } from 'lit/async-directive.js';
import { i18nController } from './i18n-controller';

class TranslateDirective extends AsyncDirective {
  render(key: string, interpolations?: Record<string, string | number>) {
    return i18nController.translate(key, interpolations);
  }
}

export const translateDirective = directive(TranslateDirective);
/** Alias for brevity inside component templates */
export const t = translateDirective;
```

Usage inside a Lit component's `render()`:

```typescript
import { t } from '@vialiq/web-components/i18n';

// Attribute binding (string result)
html`<button aria-label=${t('tabs.addTab')}>...`

// Interpolated string
html`<span>${t('tabs.moreWithCount', { count: 3 })}</span>`
// Renders: "More (3)"

// Nested inside text content
html`<span class="empty-msg">${t('combobox.noResults')}</span>`
```

Interpolation syntax in translation files: `{variableName}`

```json
{
  "tabs.moreWithCount": "More ({count})",
  "fileUpload.maxSize": "Maximum file size: {size}"
}
```

## `i18nController` — Singleton

The controller holds the currently loaded locale and translation map. It is framework-agnostic — the same singleton is shared between the web components and the host Angular app.

```typescript
// libs/web-components/src/i18n/i18n-controller.ts

export type TranslationMap = Record<string, string>;
export type TranslationLoader = (locale: string) => Promise<TranslationMap>;

class I18nController {
  private _locale = 'en';
  private _translations: TranslationMap = {};
  private _fallback: TranslationMap = {};  // always English
  private _loader: TranslationLoader = defaultLoader;
  private _loadPromise: Promise<void> | null = null;
  private _subscribers = new Set<() => void>();

  /** Configure once at app startup */
  configure(options: {
    locale?: string;
    loader?: TranslationLoader;
    fallbackLocale?: string;  // default 'en'
  }): void;

  /** Load translations for the given locale (returns a promise) */
  async load(locale: string): Promise<void>;

  /** Change locale at runtime (e.g. user switches language) */
  async setLocale(locale: string): Promise<void>;

  /** Current locale */
  get locale(): string;

  /** Translate a key with optional interpolations */
  translate(key: string, interpolations?: Record<string, string | number>): string;

  /** Subscribe to locale change (used by translateDirective to re-render) */
  subscribe(fn: () => void): () => void;  // returns unsubscribe
}

export const i18nController = new I18nController();
```

`translate()` resolves in this order:
1. Key in `_translations` (current locale) → return translated string with interpolations applied
2. Key in `_fallback` (English) → return English string (with warning in dev mode)
3. Neither → return the key itself (with warning in dev mode)

## Default Loader

The default loader fetches JSON files from a configurable base path:

```typescript
// libs/web-components/src/i18n/i18n-loader.ts

export function createFetchLoader(basePath = '/assets/i18n/wc'): TranslationLoader {
  return async (locale: string): Promise<TranslationMap> => {
    const url = `${basePath}/${locale}.json`;
    const res = await fetch(url);
    if (!res.ok) throw new Error(`[vi-i18n] Failed to load translations: ${url} (${res.status})`);
    return res.json() as Promise<TranslationMap>;
  };
}

/** Default loader — fetches from /assets/i18n/wc/{locale}.json */
export const defaultLoader = createFetchLoader();
```

Translation files are served as static assets. In a typical Angular CLI / Nx project:

```
apps/my-app/
└── public/
    └── assets/
        └── i18n/
            └── wc/
                ├── en.json
                ├── de.json
                └── fr.json
```

## Bootstrap Setup

### 1. Configure at app startup (Angular)

Call `i18nController.configure()` and `load()` **before** bootstrapping Angular. This ensures web components that render on first paint use the correct locale.

```typescript
// apps/my-app/src/main.ts
import 'reflect-metadata';                           // required by tsyringe
import { container }  from 'tsyringe';
import { i18nController, createFetchLoader } from '@vialiq/web-components/i18n';
import { bootstrapApplication } from '@angular/platform-browser';
import { AppComponent } from './app/app.component';
import { appConfig } from './app/app.config';

async function main() {
  // 1. Determine locale — from browser, user profile, or URL param
  const locale = getUserLocale();   // e.g. 'de', 'en', 'fr'

  // 2. Configure and load i18n for web components
  i18nController.configure({
    locale,
    loader: createFetchLoader('/assets/i18n/wc'),
    fallbackLocale: 'en',
  });
  await i18nController.load(locale);

  // 3. tsyringe container is already initialised at this point
  //    (ViTabsService, ViToastService, etc. are singletons in the global container)

  // 4. Bootstrap Angular
  await bootstrapApplication(AppComponent, appConfig);
}

main();

function getUserLocale(): string {
  // Priority: localStorage → navigator.language → 'en'
  return localStorage.getItem('vialiq-locale')
    ?? navigator.language.split('-')[0]
    ?? 'en';
}
```

### 2. tsyringe reflection metadata

tsyringe requires `reflect-metadata` to be imported once before any injectable classes are resolved. The `import 'reflect-metadata'` at the top of `main.ts` satisfies this.

```typescript
// tsconfig.app.json — required compiler options for tsyringe
{
  "compilerOptions": {
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}
```

**Important:** TC39 standard decorators (`accessor` keyword, Lit-style) and tsyringe's legacy decorators (`@injectable()`) can coexist in the same codebase. Use `experimentalDecorators: true` only for tsyringe classes; Lit components use native TC39 decorators which do not require this flag. The tsyringe service files live in `src/tabs/vi-tabs-service.ts`, `src/toast/vi-toast-service.ts`, etc., separate from the Lit component files.

## Runtime Locale Switching

```typescript
// Angular component — locale switcher
import { i18nController } from '@vialiq/web-components/i18n';

@Component({ ... })
export class LocaleSwitcherComponent {
  async switchLocale(locale: string) {
    await i18nController.setLocale(locale);  // loads new JSON, notifies all directives
    localStorage.setItem('vialiq-locale', locale);
    // Angular components that display translated text also need to re-render —
    // use a signal or ChangeDetectorRef.markForCheck() as appropriate
  }
}
```

When `setLocale()` resolves:
1. The new translation map is loaded.
2. `i18nController` notifies all `translateDirective` subscriptions.
3. Each directive calls `this.setValue()` on itself, triggering a Lit re-render of the affected part of the shadow DOM.
4. No full page reload required.

## Custom Loader

Implement `TranslationLoader` to load from any source (CMS, CDN, backend API):

```typescript
import { i18nController, TranslationLoader } from '@vialiq/web-components/i18n';

const cmsLoader: TranslationLoader = async (locale) => {
  const res = await fetch(`/api/translations?locale=${locale}&namespace=web-components`);
  const data = await res.json();
  return data.keys;  // { "tabs.close": "Schließen", ... }
};

i18nController.configure({ locale: 'de', loader: cmsLoader });
await i18nController.load('de');
```

## Adding a New Language

1. Copy `libs/web-components/src/i18n/locales/en.json` to `{locale}.json`.
2. Translate all string values. Do not change keys.
3. Place the output file at the serving path: `public/assets/i18n/wc/{locale}.json`.
4. The loader picks it up automatically at runtime — no code changes needed.

For right-to-left locales (Arabic, Hebrew), also:
- Set `dir="rtl"` on `<html>` in the host application.
- Web components use CSS logical properties (`margin-inline-start`, `padding-inline-end`, etc.) so RTL layout is handled automatically.

## Testing Components with i18n

In component unit tests (vitest), pre-load the English translations before mounting:

```typescript
// test setup helper
import { i18nController } from '@vialiq/web-components/i18n';
import en from '../src/i18n/locales/en.json';

export async function setupI18n() {
  i18nController.configure({
    locale: 'en',
    loader: async () => en,
  });
  await i18nController.load('en');
}

// In a test file:
import { setupI18n } from '../test/setup-i18n';

beforeAll(() => setupI18n());

it('renders close button with correct aria-label', async () => {
  const el = await fixture(html`<vi-modal open>content</vi-modal>`);
  const closeBtn = el.shadowRoot!.querySelector('[part="close-btn"]');
  expect(closeBtn?.getAttribute('aria-label')).toBe('Close');
});
```

## Storybook Integration

The Storybook preview file configures i18n before stories render:

```typescript
// libs/web-components/.storybook/preview.ts
import { i18nController, createFetchLoader } from '@vialiq/web-components/i18n';

// Load English by default; Storybook toolbar addon can switch locale at runtime
i18nController.configure({
  locale: 'en',
  loader: createFetchLoader('/assets/i18n/wc'),
});
await i18nController.load('en');

export const globalTypes = {
  locale: {
    name: 'Locale',
    defaultValue: 'en',
    toolbar: {
      icon: 'globe',
      items: [
        { value: 'en', title: 'English' },
        { value: 'de', title: 'Deutsch' },
        { value: 'fr', title: 'Français' },
        { value: 'ja', title: '日本語' },
      ],
    },
  },
};

export const decorators = [
  (story, context) => {
    const locale = context.globals.locale;
    if (locale !== i18nController.locale) {
      i18nController.setLocale(locale);  // async; directive re-renders on resolve
    }
    return story();
  },
];
```
